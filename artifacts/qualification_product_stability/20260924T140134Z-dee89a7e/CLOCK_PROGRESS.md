# Clock progress

Historical diagnostic pilot session `external-mode-check-20260924T093208-186236` contains one accepted-state gap above 150 ms: seq 2721→2722, 481.677 ms. Independent ROS `/clock` bag recorder arrival gap was 481.869 ms while source time advanced 4.000 ms. IMU observer gap was 481.517 ms with source +4.000 ms. This establishes a multi-stream upstream slowdown, not its first component. The pilot did not capture Gazebo-native clock/stats, so a Gazebo, bridge, executor, or host-specific cause is unproved.

For new runs, `--gazebo-native-diagnostic` separately observes `/world/<world>/stats` and `/world/<world>/clock` through Gazebo Transport. Its observer-loop witness distinguishes a native publication gap from delayed observation in that process. The ROS recorder remains a separate downstream clock witness. Both clocks retain source and receive times; no equality of clock domains is assumed.

The new native pilot `external-mode-check-20260924T143628-56252` observed two natural accepted-state gaps, 784.659 and 269.229 ms. In the first, native clock arrival gap was 824.248 ms with only +4 ms source progress; native stats gap was 854.867 ms with +84 ms simulation progress. In the second, native clock was 303.070/+4 ms and stats 323.794/+84 ms. The 50 ms observer loop had no >150 ms scheduling gap over either interval. Both intervals therefore show a >150 ms deficit in **native simulation progress** before the ROS clock, IMU, worker and adapter gaps. This identifies the first stalled observed layer; it does not isolate the Gazebo process's internal root cause.

The independent no-native control `external-mode-check-20260924T144205-60149` had no >150 ms accepted-state gap (max 26.813 ms). Two additional native-observer runs, `144810-63939` and `145335-67672`, also had none (max 27.969 and 29.733 ms). This small comparison does not establish that the observer caused or did not cause the first pilot's tail.

The controlled 350.272 ms `SIGSTOP` of the exact `gz sim -r -s` PID in `external-mode-check-20260924T145951-71499` produced a 373.874 ms accepted-state gap. Its native clock was 354.114/+4 ms and stats 403.888/+44 ms, with the observer loop still scheduled. The offline classifier labels the first gap `GAZEBO_SIMULATION_STALL`. A subsequent 264.478 ms accepted-state gap had live clock/IMU input and a worker/publisher gap; it is labeled `FAST_LIO_WORKER_STALL` as a post-fault observation. These labels describe observed layers, not a firmware or Gazebo defect claim.
