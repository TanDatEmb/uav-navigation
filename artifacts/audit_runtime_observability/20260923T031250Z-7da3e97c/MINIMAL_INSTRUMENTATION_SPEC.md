# Minimal diagnostic-only instrumentation proposal

**INSTRUMENTATION_REQUIRED=YES.** This is a reviewable specification for a *separate* `codex/experiment-runtime-observability-instrumentation-20260923` branch; no product instrumentation is added here. External `ros2 bag record` can capture O3 raw protocol topics without a source edit, but cannot expose O1 mission gate decisions, O2 adapter receipt, O4 world transition/lease or Hold callback generation. All new signals below have `Safety authority = NO`: no admission/control code may read them, and failure/drop of diagnostics must never alter execution.

Every record carries `run/process_incarnation`, a producer-local monotone diagnostic sequence, `steady_ns`, applicable ROS source stamp, localization/goal epoch, mission/waypoint/request and bundle/sample or world identity. A diagnostic record uses a bounded nonblocking enqueue in the hot callback; serialization/disk I/O runs elsewhere. Queue drop and sequence gaps are explicit. No callback blocks waiting for an observer. Suggested byte counts are fixed-payload estimates, **not measured overhead**; exact wire size and rate must be measured on the instrumentation branch before trials.

**Storage path for every proposed signal:** publish typed diagnostic records on a new diagnostics-only `/navigation/audit_event` stream from the bounded consumer, and capture it in the focused run's `rosbag/audit_event` alongside raw PX4 topics; normalize to the run's `audit_events.jsonl` after capture. Use distinct producer IDs for runtime and adapter. The stream and normalized file are read only by audit tooling; neither runtime admission nor adapter flight code subscribes to them. Topic/queue depth, actual payload encoding and QoS must be reviewed in the instrumentation branch. Missing records are detectable from producer sequence and queue-drop counters; the recorder's bag timestamp remains observer time.

**Non-invasive O3 capture first:** `tools/record_hold_topics.sh OUTPUT_DIR` checks topic inventory and records `/fmu/in/vehicle_command`, `/fmu/in/vehicle_command_mode_executor`, `/fmu/out/vehicle_command_ack`, `/fmu/out/mode_completed`, `/fmu/out/vehicle_status_v1`, `/clock` and `/navigation/mode_status`. Its recorder timestamp is observer time; retain PX4 message boot stamp. Verify deployed DDS YAML/binary actually advertises each topic; do not infer from source YAML alone. If topic missing, report `UNOBSERVABLE_WITH_CURRENT_TARGET` with inventory rather than silently omit. The audit harness successfully captured one complete BLOCKED smoke protocol bag after sourcing product type support; it still cannot expose adapter attempt generation or callback disposition. Existing runner `_mode_completed` filter must not be used as a Loiter event recorder.

**Input-boundary fault requirement for O4:** a separate harness must pause/drop mapping *input* or delay world publication while preserving the product's 500 ms freshness and 100 ms adapter lease. It must record injection start/end at host steady and ROS source time, exact world input sequence, and whether the vehicle remained under external mode. Do not change safety thresholds or insert a runtime fallback. If no safe pause/drop mechanism exists, design and review it on the instrumentation branch before running SITL.

**Instrumentation performance gate:** measure producer enqueue p50/p95/p99/max and queue occupancy/drop count, consumer serialization cost, and command/mission callback p99/max with tracing off/on under the same profile, seed and source/build identity. Reject instrumentation that materially perturbs the race or blocks a safety callback; no arbitrary overhead acceptance threshold is set here. Run focused model/component tests first, then ≥10 identical-provenance SITL repetitions per selected ordering/fault scenario if feasible. These observations are diagnostic and do not qualify flight authority. Remove diagnostic fields after the closure question and regression test are preserved; keep only a separately justified minimal operational witness.
