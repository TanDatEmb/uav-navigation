# Target persistent-state admission review

Each row answers independent information and exact derivability, event survival/creation/invalidation, sole writer, union eligibility, authority/replication, and loss/test if removed. `UNRESOLVED` is used where a future feature would require another contract; no field below is a generic `trajectory_ready` or `crossing_pending` bool.

| Slot | Independent fact; derivation/loss | Creation, survival, invalidation; sole writer | Union/authority/replication; invariant or test |
|---|---|---|---|
| Core `mission_` | Immutable policy/waypoints; cannot derive from a command or status. | Load once from mission YAML; survives all callbacks. Core constructor only. | Product authority, sent only as validated route/goal projections; Core initial goal test. |
| `measured_route_` | Ordered segment/fraction/arc history; latest position alone is ambiguous on loops/parallel legs. | Measured sample update; reset on localization/route identity. Core reducer only. | Orthogonal to accepted gate; self-intersection/parallel tests. |
| `identity_` | Revision/localization epoch independent; mission ID is a stable typed copy of immutable mission definition. | Created at load, revision/epoch reset at identity event. Core reducer only. | Product scope, copied read-only in crossing/receipt; reset test. |
| `gate_` | Current desired waypoint/request; not derivable from physical cursor. | Activation/acceptance; route reset. Core reducer only. | Product authority, request writer; wrong-request test. |
| `accepted_` | Last accepted gate separate from current desired and measured progress. | Acceptance; route reset. Core reducer only. | Product authority; duplicate witness test and completion predicate. |
| `previous_` | Source sample before the next possible crossing; not recoverable from latest. | First ordered sample; cleared on gap/reorder/deactivation/reset. Core reducer only. | Product measurement; skipped-ball and gap tests. |
| `latest_` | Last measured P/V sample used when a delayed receipt arrives; not the same as previous crossing endpoint. | Ordered measured update; identity reset. Core reducer only. | Product measurement; crossing-leave-ball and STOP tests. |
| `crossing_` | Typed before/after geometric event; current cursor cannot reconstruct it after leaving ball. | Physical crossing; consumed on acceptance, invalidated by identity, invalid reverse, nonordered sample or gap. Core reducer only. | Optional independent witness, not bool; PT2/PT3/reset/reverse/gap/duplicate tests. |
| `continuation_` | Exact adapter-admitted execution readiness, independent of physical crossing. | Matching receipt; consumed on acceptance, invalidated by gate/identity/deactivation, expires by command lease. Core reducer only. | Optional independent witness, not unioned with crossing; continuation-order tests. |
| `stop_confirmation_start_ns_` | Beginning of continuous slow/inside interval; cannot derive from last sample. | First eligible STOP sample; reset on gate failure/acceptance/identity. Core reducer only. | STOP-only temporal product fact; STOP test. |
| `stop_hold_start_ns_` | Beginning of waypoint hold after confirmation; distinct from confirmation start. | Confirmation elapsed; reset with STOP gate/identity. Core reducer only. | STOP-only temporal product fact; STOP test. |
| `active_` | Reducer permission granted by a consumed mode activation; no waypoint state implies it. | Activate/deactivate/complete/reset. Core reducer only. | Mutually exclusive with complete in behavior; a tagged union would combine unrelated gate data without reducing information. Initial/paused activation test. |
| Core `mode_mission_boundary_` | Latest PX4 ACTIVE/airborne source+receive witness; cannot infer from goal. | Adapter status; cleared terminal or localization reset, expires at 200 ms. Core boundary callback only. | Read-only cross-process observation, not PX4 authority; initial goal/receipt test. |
| `last_terminal_mode_activation_id_` | Terminal fence survives clearing latest status; otherwise a delayed ACTIVE restarts old mode. | Terminal status; superseded by larger terminal activation. Core boundary callback only. | Product protocol memory; delayed heartbeat test. |
| `mode_activation_id_seen_` | Last accepted process-local activation for commands even without configured mission. | ACTIVE status; monotonic within adapter process. Core status callback only. | Cross-process read-only observation; adapter replay test. |
| `mission_activation_applied_` | Which activation has already produced initial mission intent; latest status alone repeats every 50 ms. | Mission tick activation; cleared terminal/reset. Core owner transaction only. | Product deduplication; Core initial goal test. |
| `issued_mission_commands_` | Exact finite commands awaiting local admission; cannot infer from the latest published command under out-of-order delivery. | Final exposure before publish; matching receipt/lease/16-entry bound/terminal clears. Core command owner transaction only. | Cross-process handshake memory; missing/foreign/duplicate receipt integration test. |
| Adapter `mission_completion_receipt_` | Immutable Core terminal evidence needed for local `completed()` call; adapter cannot derive acceptance from command. | Matching COMPLETE receipt; clear on activation, terminal handover. Adapter boundary only. | Read-only replicated observation, no policy writer; stale-receipt test. |
| Adapter `mode_activation_id_` | Process-local lifecycle generation; cannot derive from command or ROS time. | `onActivate`; overflow fails closed. Adapter only. | PX4 authority/session fact; old-activation command test. |
| Adapter `airborne_start_ns_` | Start of local first-command acquisition window after takeoff; activation time can precede airborne by seconds. | First armed/airborne setpoint update; clear on reactivation. Adapter only. | PX4-local timer, not mission state; arming/first-command timing contract. |

The adapter's unchanged planner-recovery identity tuple refers to its **last locally admitted command** for a bounded terminal hold. It never chooses the next waypoint or request. The Core's unchanged active/staged execution identities likewise remain execution authority, not copies of accepted mission progress. No target slot is a diagnostic-only authority input.
