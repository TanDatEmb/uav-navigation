# O1 exact MissionController gate events

**Ten evaluable completed SITL episodes** are C, W1-fixed, F1, F2, R03–R06, R09 and R10. All completed five product waypoint acceptances; the C audit recorder started after waypoint 0, so its own audit stream shows only four. The compact `O1_PASS_THROUGH_EVENTS.csv` contains **39 measured PASS_THROUGH crossing/acceptance records** and **10 terminal STOP acceptance records** with mission/request/route/localization identity, controller invocation sequence, ROS callback time, previous/current odometry sequence and source stamps, crossing error/gap, continuation bundle/sample and final result. For each PASS crossing, the adapter diagnostic sequence has no internal gap spanning the relevant waypoint episode; initial recorder startup gaps are reported separately by `trace_integrity.json`.

All **39** PASS records have crossing kind `CURRENT_IN_BALL` (`phase=1`), valid measured crossing, a controller-valid continuation (`flags` bit 3), progression ready (bit 7), and waypoint accepted (bit 9) on the **same `MissionController::update()`**. In each visible episode the first recorded valid continuation precedes the crossing by **0.848–8.280 s**; C's first visible readiness can be a lower-bound witness because its recorder joined late. No `TWO_SAMPLE_SEGMENT` high-speed skip was observed. Crossing error was **0.770–0.799 m** (median 0.791 m). Every crossing pair had **20 ms** between odometry source stamps, while the product callback-time `sample_gap_s` was **4–20 ms**. This directly demonstrates why source and callback times must remain separate; it does not modify the current gate.

Classification counts: `READY_BEFORE_CROSS+CROSS_AND_READY_SAME_UPDATE` **39**, `MEASURED_STOP_ACCEPTED` **10**, `CROSS_BEFORE_READY` **0 observed**, `CROSS_BEFORE_READY_THEN_REENTRY` **0**, and `CROSS_BEFORE_READY_LOST` **0 reproduced**. The last three zero counts are **absence in the captured sample**, not a proof of impossibility. The requested crossing-first, re-entry, reverse/self-intersection and skipped-ball orderings were not forced by this nominal harness. Source code still evaluates the crossing in the current update and has no retained crossing observation (`mission_controller.cpp` around lines 460–595), so the earlier two-callback counterexample remains source-derived and runtime-unverified. No product fix is made here.

F1 requested `--inject-failed-replan-once --inject-failed-replan-after-handoff`; F2 requested `--inject-failed-replan-once --inject-failed-replan-when-safe`. Generated session parameters show the respective switches, but neither run emitted the diagnostic `injection converted` witness. They count only as nominal observed episodes, **not** as successful failure-injection evidence. R07/R08 were excluded altogether: source-manifest validation stopped their simulator before mission topics existed, so their recorder timed out. The build manifest was refreshed without changing product code before R09/R10.

No `source delay`, continuation receive delay, or distance/arc traveled for a crossing-first episode can be reported because **N=0** such episodes were observed. The event schema records exact crossing and continuation identities so a future diagnostic shadow can represent `Unknown`/pending physical observation without granting acceptance; retention policy and its quantitative bound remain a product decision. These runs are diagnostic SITL observations, not mission qualification: the evaluator reports remain `FAIL`/not qualification eligible under the unchanged relaxed-tracking experiment and versioned policies.
