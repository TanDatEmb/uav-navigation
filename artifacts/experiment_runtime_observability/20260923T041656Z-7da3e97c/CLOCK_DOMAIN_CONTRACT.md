# Clock domains and correlation

Every process records its own `steady_ns` for local order and local callback duration. **The normalizer never subtracts steady timestamps from two processes.** A numeric publish-to-receive latency is emitted only when a run-specific common ROS-clock proof is supplied to the tool and the timestamp ordering is valid. A shared `/clock` topic, absence of resets/jumps over the pair, and both nodes using that same clock must be evidenced for simulation. Without that proof, exact command identity pairing is reported as `PAIRED_IDENTITY_ONLY`.

`COMMAND_PUBLISH.ros_now_ns` is sampled just before the ROS publish call and `ros_return_ns` just after. `COMMAND_RECEIVE.ros_now_ns` is callback entry. They are *not* bag observer receive times. `source_stamp_ns` is the command's propagated-state source stamp. `MISSION_GATE.ros_now_ns` is the controller callback's ROS time, whereas `current_sample_stamp_ns` is odometry source time; the existing product crossing gap still uses callback time. PX4 VehicleStatus source stamps are PX4 boot microseconds, converted to nanoseconds only as a local source field; they are not comparable to ROS time without an explicit bridge. Bag stamps are observer time and are retained separately by normalization.
