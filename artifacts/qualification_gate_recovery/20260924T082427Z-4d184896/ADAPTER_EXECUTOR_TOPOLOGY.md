# Adapter executor topology

`src/px4/px4_navigation_external_mode/src/main.cpp:38-57` creates a separate `px4_navigation_external_mode_state_input` node and spins it on a dedicated thread using `rclcpp::spin` (single-thread executor). The PX4 ModeBase node spins separately on the main thread. The state node shares its single-thread executor among propagated odometry, typed estimator health and PX4 local-position subscriptions (`navigation_mode_node.cpp:322-353`). There are no explicit callback groups on these three subscriptions, so callbacks serialize on that node. A long health/local-position callback can delay odometry entry even if DDS has delivered its sample. The new producer-publish→adapter-callback interval cannot split DDS queueing from this executor wait; any inference must be corroborated by independent callback/clock streams or focused executor instrumentation.
