# Cross-process interface roles

| Interface | Classification | Bounded authority |
|---|---|---|
| `NavigationCommandAdmission` | `BOUNDARY_SAFETY_PROTOCOL` | Adapter reports that the **exact sampled command** passed its local frame/state/health/tracking/identity/receive-lease admission. Core pairs it with an issued finite certified command before creating a PASS continuation witness. It does not grant execution cutover, write a waypoint, or prove PX4 firmware consumption. Lost/delayed receipts never fabricate admission. |
| `NavigationModeStatus.activation_id / airborne` | `BOUNDARY_SAFETY_PROTOCOL` | Fresh ACTIVE status establishes the session and airborne start permission. The exact activation identity and explicit ACTIVE/BRAKING/non-ACTIVE transitions remain relevant; a recurring ACTIVE heartbeat older than 200 ms does not by itself revoke a session already established while exact adapter command receipts continue. Adapter-local 200 ms mode/state boundary remains unchanged. |
| `NavigationMissionProgress` | `PRODUCT_AUTHORITY_PROTOCOL` | Sole Core MissionProgress output. Waypoint events report accepted Core state; adapter is read-only. The COMPLETE event with exact mission/route/activation/accepted waypoint identity authorizes adapter terminal Hold handover. No adapter mission progression writer exists. |

**Admission conclusion: Outcome B.** Baseline `MissionController` required an accepted MAIN command for PASS progression (`mission_controller.cpp`, pinned baseline around line 569). A Core trajectory certificate alone cannot prove the PX4 adapter accepted that sample under its independent local state, health, frame and tracking boundary. The migration's exact receipt recreates that witness across the process boundary. The observed regression occurred later, when Core publication compared a retained predecessor with the advanced desired goal. It is not proof that receipt was an unnecessary prerequisite. This role is specific to finite sampled-command admission; it does not make the adapter a mission writer or impose receipt before execution cutover.
