# Stopped recovery ownership

The PlanFromRest result carries the desired revision/localization and the exact execution snapshot captured when that solve was armed. Before advancing the bounded failure window or applying its timeout, RuntimeNode requires that snapshot still current and recovery still `kStoppedRecovery`. A newer desired revision, execution activation, world recertification, or recovery transition makes the old timeout discard-only. A current stopped hold can still fail-close at the unchanged existing deadline. `PlanningTimingContract::kStoppedRecoveryTimeoutS` and measured-speed gate are unchanged.

The out-of-band planner watchdog previously held only solve generation/start time. Its `PlannerSolveActivityScope` now publishes a callback-local `PlannerSolveFailureWitness` for the same generation. The watchdog checks desired request/route/revision, localization, pending pointer and exact execution snapshot under the canonical transition locks. Stale timeout cancels only the old solve. An exact current available MAIN with valid bundle lease and fresh matching world evidence remains exposed; the publisher continues the full state/command certificate checks. Existing certified safety suffix and bounded STOPPED_HOLD retention remain. When none of those applies, exact current failure conditionally fail-closes and clears only the captured pending pointer.

The witness is in the one in-flight solve slot under the pre-existing activity mutex. It is cleared when that solve scope ends. It is not persistent execution authority and introduces no new owner or boolean latch.
