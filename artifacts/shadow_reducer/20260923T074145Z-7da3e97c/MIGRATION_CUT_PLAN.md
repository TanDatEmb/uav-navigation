# First implementation cut after this diagnostic branch

**One cut: move accepted and measured mission progress ownership to Core.** This is a future product branch plan; this diagnostic branch makes no product edits. It removes a cross-owner authority seam immediately while leaving the PX4 adapter's local lease, frame, state health and Hold protocol in place.

- **Old owner removed:** `MissionController` as writer of accepted waypoint/request and measured route cursor; `NavigationMode` as writer of `mission_terminal_`, last-completed waypoint/request and mission-progress recovery mirrors. The adapter receives Core's immutable mission-progress result for output/reporting only.
- **New owner introduced:** Core `MissionProgressState` with `RouteIdentity`, ordered `RouteCursor`, optional typed crossing witness, current gate `(waypoint,request_id)`, accepted gate and continuation witness. Only Core's serialized transition loop may accept a waypoint. `RouteProgress` remains a pure geometry/measurement helper, not an acceptance writer.
- **Fields deleted:** `MissionController.checkpoint_valid_`, `trajectory_ready_`, `terminal_hold_pending_` as independent acceptance latches; `NavigationMode.mission_controller_`, `mission_` policy mirror and `mission_terminal_`. Exact replacement predicates are computed from the new state and certified execution evidence.
- **Fields moved:** `MissionController.route_progress_`, `previous_position_`/time, `active_waypoint_index_`, `request_id_` to Core-owned measured/accepted state; adapter's last-completed receipt becomes a read-only delivery receipt if deduplication is required, not an acceptance authority.
- **Fields derived:** `missionComplete(route, accepted_gate)`, `successorReady(continuation, gate)`, `crossingValid(route, localization, source stamps, ordered cursor)`, `terminalHoldEligible(measured_stop, execution)`. No pending bool.
- **Interfaces changed:** measured odometry/state with source stamp, localization epoch and route identity enters Core; planner MAIN continuation witness enters Core; Core emits immutable `{mission, route, gate, accepted, next goal intent, execution generation}` transition record. PX4 adapter consumes this record and existing `ControlReference` with a monotonically identified session. Adapter cannot publish a new NavigationGoal on its own; it may still locally reject a reference or initiate Hold for its boundary contract.
- **Tests required:** PT1–PT6 plus inside-ball/skipped-ball/sharp corner/coincident PASS→STOP/self-intersection/reverse/odometry-gap component tests; old/new shadow differential on O1 records; cross-process session/epoch rejection; W2–W5 fence preservation; STOP measured confirmation; adapter no-policy-writer static check. Build OFF/ON instrumentation separately and do representative SITL before any authority cutover.
- **Rollback boundary:** ship behind an explicit build/runtime selection of old-vs-Core mission authority, with exactly one active writer per run and immutable event receipts for comparison. Roll back the entire mission-authority cut if acceptance or goal order differs outside a documented policy change. Never dual-write accepted progress, never relax safety gates for parity.

The cut does not resolve PX4 `ModeCompleted` policy, real lease timing tails, or E2 exported API ownership. Those are named separate boundary tasks and must not be silently bundled into mission-progress migration.
