# Explicit target policy choices for the diagnostic model

These choices do not change product behavior.

1. A measured PASS witness survives a callback and an exit from the acceptance sphere while the same mission, route, localization epoch, waypoint and request remain active. It is consumed exactly once after a matching continuation. This removes callback timing as a mission-progress authority. A route/localization/gate change or confirmed reverse through its route-relative boundary invalidates it. A two-sample witness requires positive source ordering and gap ≤250 ms, copied from pinned source; an inside-ball witness can be single-sample. This is conservative about stale identity but intentionally permits crossing-first acceptance later.
2. The shadow uses a route segment plus optional `u` and source sample identity. The trace lacks full route geometry, so replay uses waypoint ordinal as an **inferred route cursor**; it cannot prove self-intersection branch choice. Production migration requires exact route-relative projection/geometry tests.
3. Committed safety stopping is one-way until measured stop. Recoverable braking remains a distinct representable phase for a certified continuous recovery, but this diagnostic reducer does not infer such an episode from a generic BACKUP role. An exported `onTrajectory` call with unknown owner is not allowed to prove recovery policy.
4. Downstream Hold request or lease expiry fences the current execution generation. Fresh world may update context but cannot rearm that generation. A new explicit session may start after the fence; startup Hold before any observed generation is classified as a new-session inference only after downstream valid command receive, not old-session resurrection.
5. ACK and `ModeCompleted` are protocol observations. A post-request, source-monotone AUTO_LOITER VehicleStatus is labeled **Hold observed**, not formal PX4 authority transfer. Missing status leaves retry logically required; external PX4 command/retry policy remains a named integration blocker. A later non-Hold status removes Hold observation and records an unknown takeover cause.
6. Trace gaps do not mean false. Exact command pair ambiguity is `INSUFFICIENT_TRACE`; startup truncation and bag-observer inversions are reported separately. A single callback's complete acceptance audit can be compared locally despite unrelated earlier gaps. Cross-process observer order is not a happens-before proof.
