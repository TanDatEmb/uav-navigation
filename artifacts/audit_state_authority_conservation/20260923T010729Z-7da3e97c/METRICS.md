# Scoped quantitative metrics

`tools/metrics.py` produces `metrics.json` from TARGET declarations and three selected identity paths. It reports 239 behavioral **candidates**, 79 diagnostic/test **candidates**, 60 bool-like and 26 optional-like behavioral candidates, 16 mutex declarations, 73 non-constant `NavigationCommand` fields and 52 occurrences of selected identity helper names (33 runtime source, 19 Store header). The command schema preliminary split is 6 control, 13 safety-admission, 7 provenance and 47 diagnostic fields. Selected publication code nests three runtime locks and Store lock, giving a verified depth lower bound of four for that path.

These are scoped proxies. The 52 occurrences include definitions and repeated calls, not 52 manual multi-field comparison sites; zero in the selected adapter file does not mean no identity comparison there. The 16 mutex declarations include worker/diagnostic locks, not 16 control-path locks. Whole-product authority owner count, state writer count, independent FSM count, optional/latch owner count, manual comparison sites, cross-owner atomic transitions and product-wide nested-lock maximum remain **UNRESOLVED**. A compiler-aware inventory and call graph are required before using their reduction as a migration success metric.

Target budget is a proof obligation rather than a field quota: one mission/execution decision writer; zero worker execution commits; no permanent replicated mission/execution semantics in PX4; no diagnostic field used by admission; fewer verified cross-owner transactions/comparison sites/control locks; no worse p99 command latency or queue overflow under representative input bursts. Independent physical and protocol fields may increase the raw field count.
